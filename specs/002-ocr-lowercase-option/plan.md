# Implementation Plan: OCR Result Lowercase Toggle

**Branch**: `002-ocr-lowercase-option` | **Date**: 2026-06-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-ocr-lowercase-option/spec.md`

## Summary

Add a `lowercaseResult` boolean toggle (default `true`) to the shared config schema so
that the userscript's View layer can convert the normalized OCR text to lowercase before
writing it into the captcha answer field, with a matching Switch control on the config
page. The schema version bumps from `1` to `2` with a zero-loss additive migration.

## Technical Context

**Language/Version**: TypeScript 5.x under `strict` mode (all three packages)

**Primary Dependencies**: pnpm + Nx monorepo; `vite-plugin-monkey` (userscript build);
`@vitejs/plugin-react` (config page); Vitest (tests); shadcn/ui + Tailwind v4 (config page)

**Storage**: GM userscript storage (JSON string), bridged to config page via postMessage

**Testing**: Vitest with jsdom environment; `nx run-many -t typecheck test build`

**Target Platform**: Tampermonkey/Violentmonkey-compatible userscript (Chromium/Firefox);
React SPA on GitHub Pages (config page)

**Project Type**: Nx monorepo with three packages:
- `uit-student-captcha-config-core` — shared schema/validation library
- `uit-student-captcha` — userscript (MVVM, Model/ViewModel/View)
- `uit-student-captcha-config-page` — React SPA config editor

**Performance Goals**: No measurable impact — `.toLowerCase()` on a short string is O(n)
and below any perceptible threshold.

**Constraints**: Constitution I (MVVM layer boundaries); Constitution III (strict TS);
Constitution IV (configurable defaults); Testing Discipline (jsdom unit tests required).

**Scale/Scope**: Three files changed across three packages + test updates. No new packages,
no new dependencies, no new resolvers.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked after Phase 1 design.*

### Constitution I — MVVM layer boundaries ✅

The lowercase transform lives exclusively in `PortalView.fillAnswer()` (View). The
ViewModel receives the `OcrResult.text` unchanged. No resolver or ViewModel code changes.

### Constitution II — Provider abstraction ✅

No resolver code changes. The registry/factory is untouched. The new field is a global
config option, not a per-provider branching condition.

### Constitution III — Strict type safety ✅

`ProviderConfiguration.lowercaseResult: boolean` is explicitly typed. `PortalViewOptions`
gains `lowercaseResult?: boolean`. `GlobalSettingsProps` gains the two new props. All
callers are updated. `pnpm exec nx run-many -t typecheck` must pass with zero errors.

### Constitution IV — Configurability ✅

`lowercaseResult` is a config field with a typed default (`true`), validated and
coerced by `validateConfig()`. It is not a hardcoded constant.

### Constitution V — Minimal footprint ✅

No new runtime dependencies. No new `@grant` privileges. DOM access is unchanged (still
only `#edit-english-captcha-answer`). The transform is a single `.toLowerCase()` call.

### Testing Discipline ✅

New unit tests required for:
- `config-core`: `validateConfig()` coercion of `lowercaseResult` (3 cases in validate.spec.ts)
- `userscript`: `PortalView` fillAnswer with flag `true`/`false`/absent (3 new assertions in PortalView.spec.ts)
- `config-page`: `GlobalSettings` Switch rendering and toggling (2 new assertions)

### Complexity Tracking

No violations — all gates pass. The Complexity Tracking table is not required.

## Detailed Change Notes

### 1. `config-core/src/schema.ts`

```ts
// Add to ProviderConfiguration:
readonly lowercaseResult: boolean;

// Update version literal:
readonly version: 2;
export const CONFIG_VERSION = 2 as const;

// Update DEFAULT_CONFIG:
export const DEFAULT_CONFIG: ProviderConfiguration = {
  version: CONFIG_VERSION,
  timeoutMs: 15_000,
  providers: [],
  lowercaseResult: true,
};
```

### 2. `config-core/src/validate.ts`

Inside `validateConfig()`, after the `timeoutMs` line:

```ts
const lowercaseResult = asBoolean(obj['lowercaseResult'], true);
```

Update the return statement:

```ts
return { version: CONFIG_VERSION, timeoutMs, providers, lowercaseResult };
```

### 3. `userscript/src/view/PortalView.ts`

`PortalViewOptions` gains:
```ts
readonly lowercaseResult?: boolean;
```

`PortalView` stores it as a private field in the constructor:
```ts
private readonly lowercaseResult: boolean;
// constructor:
this.lowercaseResult = options.lowercaseResult ?? true;
```

`fillAnswer()` applies the transform before writing:
```ts
const finalText = this.lowercaseResult ? text.toLowerCase() : text;
input.value = finalText;
```
The two `dispatchEvent` calls use `finalText` but are otherwise unchanged.

### 4. `userscript/src/main.ts`

```ts
const view = new PortalView(viewModel, {
  configUrl: CONFIG_PAGE_URL,
  lowercaseResult: config.lowercaseResult,
});
```

### 5. `config-page/src/components/GlobalSettings.tsx`

Extend props and render a `<Switch>` below the timeout input. Import `Switch` and `Label`
(already available via shadcn/ui).

```tsx
export interface GlobalSettingsProps {
  timeoutMs: number;
  onChange: (timeoutMs: number) => void;
  lowercaseResult: boolean;
  onLowercaseChange: (v: boolean) => void;
}

// Render addition (inside the <section>):
<div className="flex items-center gap-3">
  <Switch
    id="lowercaseResult"
    checked={lowercaseResult}
    onCheckedChange={onLowercaseChange}
  />
  <div>
    <Label htmlFor="lowercaseResult">Lowercase OCR result</Label>
    <p className="text-xs text-muted-foreground">
      Converts the recognized text to lowercase before filling.
      Recommended — portal captchas are lowercase.
    </p>
  </div>
</div>
```

### 6. `config-page/src/App.tsx`

Pass the two new props to `<GlobalSettings>`:

```tsx
<GlobalSettings
  timeoutMs={current.timeoutMs}
  onChange={(timeoutMs) => update({ ...current, timeoutMs })}
  lowercaseResult={current.lowercaseResult}
  onLowercaseChange={(lowercaseResult) => update({ ...current, lowercaseResult })}
/>
```
